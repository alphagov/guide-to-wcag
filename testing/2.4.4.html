How to test for 2.4.4 Link Purpose (In Context)

WCAG says:

The purpose of each link can be determined from the link text alone or from the link text together with its programmatically determined link context, except where the purpose of the link would be ambiguous to users in general.

When this is applicable

If there are links.

Check link texts

Check that link text either:

  • informs about the target or purpose - using a URL as the link text might be sufficient if it’s obvious or descriptive enough, though this is not ideal
  • has context (in text or as an image alt) around it that informs about the link’s target or purpose - this could be in same block of text, in the heading or parent list item it sits under, in same table cell or associated table header
  • has an accessible name

For links to other file formats (anything other than web pages), also check the link text mentions the file format or the format and behaviour is clear from its text (like email addresses).

Exceptions

If the purpose of the link is unclear to everyone, including people without impairments, this is not a WCAG fail, although it would generally be considered poor usability.

Best practice

  • Avoid using ambiguous link text such as “click here” or “read more”, especially for anything related to accessibility, such as links to alternative accessible versions or the accessibility statement
  • For ambiguous link texts that cannot be improved, text that provides the context should be in front of the link text - for example, “To learn more about how to book our town hall [link]click here[/link]”
  • Avoid using URLs as the link text, unless it’s for printing purposes or in an email

Other ways to test

To see a list of all links to find out if any of them go to a different format, use the Web Developer extension and go to ‘Information > View Link Information’. Note this might miss out links that are redirects to other formats.
