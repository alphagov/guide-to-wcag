How to test for 2.4.7 Focus Visible

WCAG says:

Any keyboard operable user interface has a mode of operation where the keyboard focus indicator is visible.

When this is applicable

When there are interactive elements (links, form elements or other interactive objects).

Tab through

Check:

  • that you can always visually see where you are on the screen when tabbing through interactive elements
  • skip links have at least a visible focus

If visual focus is barely noticeable, consider failing it (because it’s “difficult to see” as suggested in F78). Consider other factors such as different monitors, lighting conditions or tester’s abilities. If in doubt, fail it or ask others for a second opinion.

The visual focus will also need to meet 1.4.1 Use of Colour and 1.4.11 Non-text Contrast.

It’s okay if:

  • a visually hidden element receives visible focus (but it might fail 2.4.4 Link Purpose)
  • a seemingly single element receives visible focus multiple times
  • an element receives focus in some way but doesn’t do anything when you try to interact with it (this might fail under 1.3.1 Info and Relationships or 4.1.2 Name, Role, Value)

Best practice

  • invisible or non-interactive elements shouldn’t receive focus
  • skip links should always be visible, not just when they are focused

Mobile app testing

Use an external keyboard.
