# 2.4.7 Focus Visible

## [WCAG says](https://www.w3.org/TR/WCAG21/#focus-visible):

> Any keyboard operable user interface has a mode of operation where the keyboard focus indicator is visible.

## When this is applicable

When there are interactive elements (links, form elements or other interactive objects).

## Tab through

Check:

* that you can always visually see where you are on the screen when [tabbing through](keyboard) interactive elements
* skip links have at least a visible focus

If visual focus is barely noticeable, consider failing it (because it's "difficult to see" as suggested in [F78](https://www.w3.org/WAI/WCAG21/Techniques/failures/F78)). Consider other factors such as different monitors, lighting conditions or tester's abilities. If in doubt, fail it or ask others for a second opinion.

It's okay if:

* a visually hidden element receives a **visible** focus (but it might fail [2.4.4 Link Purpose](2.4.4))
* a seemingly single element receives visible focus multiple times
* an element receives focus in some way but doesn't do anything when you try to interact with it (this might fail under [1.3.1 Info and Relationships](1.3.1))

## Best practice

* invisible or non-interactive elements shouldn't receive focus
* if a colour change (including browser default colours) is the only means of indicating focus, the contrast between focused and unfocused interactive elements should be at least 3:1 - this requirement will be in WCAG 2.2
* skip links should always be visible, not just when they are focused
