2.5.4 Motion Actuation (A)

Users must be able to perform tasks without needing to move their devices or make gestures at the screen.

What WCAG says:

Functionality that can be operated by device motion or user motion can also be operated by user interface components and responding to the motion can be disabled to prevent accidental actuation, except when:

Supported Interface: The motion is used to operate functionality through an accessibility supported interface

Essential: The motion is essential for the function and doing so would invalidate the activity

Check the official guidance for Understanding 2.5.4 Motion Actuation

What this means

Users must be able to perform a task without needing to perform gestures at the screen or tilt or shake their device. They should be able to use buttons, links or other controls instead.

They must also be able to disable motion controls completely.

The only exceptions are if the motion control can operate in an accessible way or if it is essential for a function, like a pedometer that requires users to walk to count steps.

Why it matters

Some people with motor impairments will not be able to move themselves or their device in the required manner and so will be prevented from performing tasks.

How to check

Use a mobile device that has a motion sensor. Shake the device, move it physically around in multiple dimensions and move your hand around in front of the device.

If any functionality is triggered, check:

  • it can also be triggered using a common alternative method, for example arrow buttons to move around in a game with a keyboard
  • motion input can be deactivated (deactivation in the system settings is fine)

How to test in detail for 2.5.4 Motion Actuation

Common mistake

Only motion controls can be used

For example, an app requires users to tilt their phone to move to the next page. There are no alternative ways of moving pages and no way to disable the motion controls.

This would fail as it means users who are not able to move their phone in the required way would not be able to use the app.

It could be fixed by including an alternative way of moving pages, like an arrow button, and a way to turn off the motion controls.

Good example

Motion controls are one option

For example, an app allows users to move their phone to change the view of an image. It also allows users to select buttons to change the view and to disable motion controls.

This would pass as it gives an accessible alternative to moving the phone and a way to turn off motion controls.

Related success criteria

  • 2.5.1 Pointer Gestures (A) requires that users must not need to use complex touch gestures to perform a task, like swiping or pinching.
  • 2.5.7 Dragging Movements (AA) requires that users must be able to complete a task without having to make a dragging motion on their screen.
